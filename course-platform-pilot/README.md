# Mr Flynn IB course platform pilot

This is an isolated, local-only prototype of the future student course experience. It does not change or deploy the public MrFlynnIB website.

## Included

- AA SL, AA HL, AI SL and AI HL course experiences
- A student-facing entitlement model: the current prototype learner owns AA HL and sees only that course after sign-in; the four-course catalogue belongs before purchase
- All five syllabus topics for every course
- 441 verified, student-facing Bunny Stream course videos across 20 organised collections
- 640 Teachable-aligned lesson placements across the four courses
- Complete student-facing course pathways without internal sharing labels
- Real Bunny Stream playback, topic navigation and whole-course search
- Two-question lesson practice generated only for lesson-level matches that pass the current semantic audit; uncertain lessons are withheld rather than padded with broadly related questions
- Lessons without two defensible matches are deliberately held for further curation rather than filled with broad, repeated or weak same-subtopic questions
- A top-level past-paper solutions hub with course, session, paper and question navigation
- 1,280 verified Teachable-to-Bunny past-paper solution placements across the four IB courses
- Lesson completion, practice-question completion and per-question whiteboard work stored only in the browser for this private prototype
- Course and topic progress views
- Responsive desktop and mobile layouts
- Prototype single-login screen
- A private `?v=all-courses-review` mode that exposes AA HL, AA SL, AI HL, AI SL and Edexcel IGCSE Mathematics together for pre-launch inspection without changing the single-course student entitlement model

## Not yet production functionality

- Real authentication or password storage
- Payments and access expiry
- Secure signed Bunny playback tokens
- Persistent server-side progress
- Email or account administration

Serve the repository root locally, then open `/course-platform-pilot/dist/`.

For the private five-course inspection page, open `/course-platform-pilot/dist/?v=all-courses-review`.

`dist/library-data.js` is a static, non-secret snapshot of the Bunny library metadata used by the prototype. Refresh it with `generate-library-data.mjs`, passing the verified Bunny snapshot and Teachable catalogue paths. The generator includes only ready AA/AI course collections, maps the exact Teachable lesson catalogue, removes exact duplicate records, prefers combined and Teachable-edit versions, and keeps deliberately suppressed videos out of the student preview.

`dist/past-paper-data.js` is generated by `generate-past-paper-data.mjs` from the Teachable-to-live-Bunny reconciliation and the usable Bunny snapshot. It accepts verified mappings plus exact same-collection, same-question live titles after removing internal sharing notes such as `(2sl)`. Part files and unrelated fuzzy matches remain excluded. The student catalogue groups papers by year, session, timezone and paper, and writes no Bunny API key to the project.

`dist/video-audit.html` is a private, unlinked QA screen covering every Teachable-aligned IB course lesson and past-paper solution. `generate-video-audit-data.mjs` combines the exact website selections, reconciliation and Bunny snapshot into `dist/video-audit-data.js`. The page exposes title, duration, collection, video ID, Teachable source link and embedded Bunny playback, and keeps review and missing items visibly separate from confirmed matches.

`dist/practice-data.js` is generated by `scripts/generate-practice-data.mjs` from the verified IB and IGCSE question banks and the exact lesson catalogues. It assigns a canonical course bank to shared SL-and-HL videos, so an SL lesson and the same shared HL lesson always display one identical question set. It excludes off-syllabus and provisional questions, validates curated overrides as well as generated candidates against the precise lesson skill, and strongly prefers questions of eight marks or fewer. A broad syllabus-subtopic match is not sufficient. Lessons without two genuinely suitable records remain unmapped and visible in `practice-audit.csv` as `needs-review`; lessons Rob explicitly exempts from practice are recorded separately as `not-applicable`. AA question cards display **Paper 1 · Non-calculator** or **Paper 2 · Calculator** using the course-specific paper mapping in the bank. AI HL question cards show simply **Calculator**, because every paper permits calculator use and the paper number adds no useful lesson-practice information. IGCSE deliberately does not expose source-paper metadata. The audit records every mapping, selection method, mark total and paper/calculator classification. Treat its generated counts as QA results, not fixed product copy.
